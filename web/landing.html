Building a robot skill from a sentence needs a frontier model to plan the task, critique the failures and optimize the next round. Here that is Meta Llama, running in parallel with SubQ. Say what the arm should do, and Dojo trains a policy for it and measures it on scenes it never trained on. If the task needs more than one arm, ask for another SO-101 in the same chat and each arm gets its own sub-task.

How it works

One sentence goes in. Eight agents hand it down the pipe.

Every stage streams its logs, demos, loss and evaluation to the page as it happens.

  1. 01

    Prompt

    A planner turns the sentence into a task and a success check the simulator can evaluate. It runs on Llama 4 Maverick, and the app names the model that answered.

  2. 02

    Route

    The router picks the nearest skill in the library, or the base policy, and checks the robot can do the task.

  3. 03

    Scene

    MuJoCo builds the table and 20 held-out layouts the policy never sees in training.

  4. 04

    Demos

    A scripted expert collects demonstrations with randomised colours, positions and noise.

  5. 05

    Train

    The action head of the VLA is fine-tuned from the nearest skill, on one Mac.

  6. 06

    Eval

    Twenty rollouts on the held-out scenes. Success is counted, not claimed.

  7. 07

    Critic

    It reads the failed rollouts and retrains near them if there is time left.

  8. 08

    Publish

    The skill joins the library and becomes its own agent that other agents can call.

Inputs to the policy: two camera images, the instruction and the joint positions. Output: the next 10 joint targets. Budget: 3 minutes per prompt.

Llama and SubQ

Two models, side by side. Plain code for the rest.

Meta Llama 4 Maverick parses the task, plans the arms and reads the failures. SubQ, a long-context model, reads the whole run history, every past round and the skill library. In each optimizer round both propose a change at the same time, both are scored in simulation, and the round records whose change won. The app shows which backend really answered.

  • taskParses the sentence into a task and a success check.Llama 4 Maverick
  • criticReads the failed rollouts and picks what to train next.Llama 4 Maverick
  • optimizerEach round, Llama and SubQ each propose a change; both are scored and the better one is kept.Llama + SubQ
  • routerPicks the nearest skill and checks the robot can do the task.code
  • plannerSplits a task across arms.Llama 4 Maverick
  • scene, data, trainer, evalBuild the scene, collect demos, fine-tune, and score on held-out layouts.code
  • registrySaves the skill so the next task can start from it.code

Several arms

One chat, one arm or several.

Ask for "another SO-101", or describe a task that needs more than one arm. The planner gives each arm a sub-task and the router checks the robot can do it. Each arm is either a trained VLA or a script, and they run in order.

Skill library

Every prompt grows the library.

Each published skill is saved with its measured score and starts the next prompt. The nearest skill is the starting point, so later skills train faster.

Kitting into a tray slot, insertion into a socket and rotate-and-place are the hardest skills and score lowest. Scores are measured on 20 held-out scenes each, trained inside the 3 minute budget.

Robot builder

Pick an arm, a wrist and a gripper. Every part is sourced.

The builder only offers parts that exist as published open-source MuJoCo models. It composes them into one file, checks reach, joint limits and grip, then trains the next skill on that robot. Nothing here was modelled from scratch.
